## **1️⃣ Your Goal: Hackathon Problem Statements**

This hackathon revolves around **leveraging Vercel’s agent stack as your launchpad and reaching for the stars by tapping into the power of the Gemini to create intelligent agents that can think, plan, and execute**.

Your project must build in **at least one** of the three required problem statements below:

- **Statement One: Chat-Based Agents**

  - Build an agent that lives where your users already are. Using Vercel's ChatSDK, create agents that plug directly into platforms like Slack, Discord, Microsoft Teams, WhatsApp, Google Chat, GitHub, or Linear — no new app to install, no new tab to open. Write your bot logic once and deploy it across multiple platforms from a single codebase. Bonus points for leveraging Gemini's multimodal capabilities to handle images, files, and rich media within the conversation.

  - Example projects:

    - Code Review Bot — A GitHub agent that watches for new PRs, spins up a sandbox, runs the code, and posts a detailed review with suggestions directly in the PR thread. Bonus: understands screenshots of UI bugs attached in issues.

    - Slack Ops Agent — An agent that lives in your team's Slack workspace. @ mention it to check deploy status, roll back a release, query your database, or summarize a noisy channel — all without leaving Slack.

    - Discord Community Manager — An agent that moderates a Discord server, answers FAQs with context from your docs, auto-tags posts by topic, escalates tricky questions to humans, and can analyze screenshots or images members share for troubleshooting.

    - Linear Triage Agent — Monitors new Linear issues, auto-labels and prioritizes them based on content and past patterns, requests missing info from the reporter, and suggests which team member should own it.

- **Statement Two: Multi-Modal Agents** 

  - Build an agent that goes beyond text. Leverage Gemini's multimodal capabilities to create agents that see, hear, or understand the world through images, video, audio, documents, or any combination. Think agents that can watch a livestream and act on it, analyze visual data to make decisions, or navigate rich media environments autonomously.

- **Statement Three: AI Applications**

  - Build an AI-powered application that solves a real problem. It doesn't have to be a fully autonomous agent — it just has to be useful, creative, and well-built. Think AI-native products that people would actually want to use: tools that generate, analyze, transform, or simplify something in a way that wasn't possible before. The focus is on craft, user experience, and shipping something polished.

**🔟 Judging Process**

Judges will be taking place on **Saturday, March 21**. These judges are evaluating your **technical demos** in the following categories. *Show us what you have built* to solve our problem statements. Please **do not** show us a presentation. We'll be checking to ensure your project was built **entirely during the event**; no previous work is allowed. 

**|** Judging proceeds in two rounds:

**Round One:** Hackers will be assigned to judging groups in different rooms of the venue. Each team will have \~3 minutes to live demo their project, followed by 1-2 minutes of Q&A. The following criteria will be used:

- Impact Potential (20%) — What is the project’s long-term potential for success? Will this project have a long-lasting impact on the industry, world, or any other areas? How useful and substantial is this project beyond the scope of the hackathon?

- Live Demo (45%) — How well has the team implemented their core idea? Does it work well live? How is it presented?

- Creativity and Originality (35%) — Has this concept been seen before? In what ways does this project differentiate itself, and what innovations does it bring to its respective field? Does it tackle the problem statements in a unique way?

**Round Two:** The top six teams demoing on stage in front of a panel of judges & all attendees. Each team will have \~3 minutes to live demo their project, followed by 1-2 minutes of Q&A. The same criteria as above will be used, though with equal weighting for each category.
